# Existing-plan review

Audit first; do not silently replace the learner's plan. Review, in priority order:

- target capability and role clarity;
- baseline and prerequisites;
- current technical/version accuracy;
- dependency order and time capacity;
- course quality, duplication, and source credibility;
- proportional technical-quality practice;
- real work, portfolio, and verification evidence;
- risks, trade-offs, and decision gates;
- documentation, navigation, and stale claims.

Report each issue like this:

```md
## Finding: <short title>
Severity: must fix | should fix | worth noting
Plan section: <file and heading>
Problem: <specific issue>
Why it matters: <real consequence>
Evidence: <verified source or stated limitation>
Recommendation: <concrete correction>
Decision needed: <only if the learner must choose>
```

Ask only the next decision-changing question. Produce a revised plan only after the learner requests or approves that direction.
