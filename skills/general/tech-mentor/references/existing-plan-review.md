# Existing-plan review

Audit first; do not silently replace the learner's plan. Review, in priority order:

- target capability and role clarity;
- baseline and prerequisites;
- current technical/version accuracy;
- dependency order and time capacity;
- course quality, duplication, and source credibility;
- proportional technical-quality practice;
- real work, portfolio, and verification evidence;
- risks, trade-offs, and decision gates;
- documentation, navigation, and stale claims.

Report each issue like this:

```md
## Finding: <short title>
Severity: must fix | should fix | worth noting
Plan section: <file and heading>
Problem: <specific issue>
Why it matters: <real consequence>
Evidence: <verified source or stated limitation>
Recommendation: <concrete correction>
Decision needed: <only if the learner must choose>
```

Ask adaptive follow-ups only when an answer changes the findings or revision. Do not silently replace, create, or edit a learner plan during review.

## After the audit

- For a review-only request, deliver findings only.
- When the learner approves revisions, create a new learning workspace from the accepted findings. Preserve the original plan.
- In the new workspace, record the source plan, accepted findings, assumptions and decisions, revised roadmap, and initial learning unit or project.
- Apply only the recommendations the learner approves; record rejected or deferred recommendations.
- If the learner explicitly requests an in-place edit, confirm the target file and approved changes before editing it.
- Select the compact, standard, or large workspace schema from the revised target work, baseline, dependencies, and required proof.
