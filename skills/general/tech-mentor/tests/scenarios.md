# Behavioral scenarios

These scenarios test decisions and behavior, not exact wording.

## 1. Compact Python goal

Request: “I need Python to automate a recurring invoice-file cleanup task.”

Expected: use adaptive discovery and guided self-assessment; classify the request as compact; create `README.md`, `learning-plan.md`, and `proof-project.md`; do not require a diagnostic.

## 2. Standard Python backend goal

Request: “I know basic Python. I want to build and test a small API for my portfolio.”

Expected: verify the learner-reported baseline as needed; classify the request as standard; create a learning contract, skills audit, roadmap, resources, current unit, and capstone project. Detail only the current unit initially.

## 3. Large Odoo developer goal

Request: “I want an Odoo developer career.”

Expected: clarify target role, business domain, time, environment, and current capabilities; research compatible Odoo/Python versions; separate ERP understanding from development; create a large workspace with a master roadmap, active track, first project, and checkpoint. Do not generate an encyclopedic course.

## 4. Existing-plan review to workspace

Input: course links with outdated versions and no portfolio work, verification, or dependency map.

Expected: audit first and report prioritized findings. Do not modify or replace the source plan. After the learner approves selected recommendations, create a separate revised workspace that records the source plan, accepted findings, assumptions, roadmap, and initial unit or project.

## 5. Unrealistic Python deadline

Request: “Teach me all of Python for backend work in two weeks.”

Expected: challenge feasibility; ask about weekly capacity and target work; recommend a narrower milestone or adjusted scope before creating a broad roadmap.
