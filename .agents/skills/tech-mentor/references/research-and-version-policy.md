# Research and version policy

Research before making current or technical claims. Prefer:

1. Official documentation, release notes, lifecycle/support policy, repositories, specifications, and standards.
2. Maintainer or vendor technical material.
3. Primary research or authoritative role data for career evidence.
4. Credible independent sources only to fill gaps such as trade-offs or course experience.

Use direct source links, not search-result pages. For every time-sensitive claim record the source, access/review date, and status: `current`, `deprecated`, `planned`, `uncertain`, or `inferred`.

## Version decisions

Record candidate versions and lifecycle status, compatibility with the learner's ecosystem/employer/project and deployment environment, the selected version and rationale, and what changes if another version is required. “Newest” is not a selection rule.

Separate sourced facts from analysis. Treat vendor marketing as a claim, never independent evidence. State assumptions, uncertainty, and missing evidence. If live research is unavailable, say so and analyze only sources the learner supplies.
